# Why Bespoke is not a universal engine

One explicit family of glyph recipes can produce many **Bespoke derivatives**, but cannot express arbitrary serif, humanist, calligraphic, or radically different sans constructions without new recipes. The current sliders alter shared numeric values and curve macros; they do not expose `a/g/4/0/Q/R` construction choices, local per-glyph variation, or a style-engine grammar. Source `font.mf` exposes 16 controls; future candidates such as mono transition, optical text/display, tech/neutral and terminal angle are absent or only partially approximated by current values.

Conflicts are structural and optical: thick pen + narrow unit closes counters; increased x-height + cap/ascender changes break vertical rhythm; aperture + taper can collapse joins; high contrast + aggressive superness changes curvature; slant alters sidebearings. One fixed point topology is not guaranteed across extremes, especially after METAFONT-to-outline conversion. No UFO masters, Designspace or variable-font compatibility checks exist in inspected site/Bespoke sources.

Latin + Cyrillic requires an authored Cyrillic repertoire, distinct glyph grammar and spacing groups, localized forms, accent marks, script tests and quality review by a Cyrillic-aware designer. T1 Latin encoding is insufficient. Text↔Display requires coordinated optical design (apertures, joins, spacing, details), not a uniform stroke change. Proportional↔Mono requires coordinated advances and redesigned narrow/wide forms; changing advance widths alone damages rhythm. Variable fonts require compatible contour counts/order/directions, components, anchor positions and master metrics for each topology family. Discrete switches belong in alternate glyphs/export variants, not one continuous axis unless each branch is separately compatible.

Metaflop source is GPLv3 and Bespoke source headers say GPLv3, so source reuse also crosses a licensing boundary. Use it as evidence for interaction and parametric thinking; create original recipes.
