# Recursive as a variable architecture reference

[Official source README](https://github.com/arrowtype/recursive) documents five axes: `MONO` 0–1, `CASL` 0–1, `wght` 300–1000, `slnt` 0 to -15, `CRSV` 0/0.5/1. The latter is a named behavior choice inside a variable-font design, not evidence that any structural switch can interpolate. [Designer process notes](https://github.com/arrowtype/recursive-minisite/blob/main/process.md) report 24 source fonts and 1,248 glyphs per source for the historical build, with thousands of hand-edited drawings. This is strong evidence that multi-axis mono/sans quality demands authored masters and tooling, not simply changing advances.

The transferable lesson is **curated compatible sources + scripted build/preparation + named use cases**. PFL should start with one compatible weight dimension and a small Latin/Cyrillic corpus, then expand only when quality gates pass. Recursive's outlines and OFL-covered font software are not PFL source material. `MONO` naming is a precedent for a custom uppercase tag, not a commitment to ship PFL mono in V1. Historical counts are quoted as project-specific evidence, not a universal master-count formula.
