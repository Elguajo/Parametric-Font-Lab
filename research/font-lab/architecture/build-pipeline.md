# Proposed source-to-font pipeline

`versioned project JSON → deterministic recipe evaluator → contour/metrics validation → compatible UFO masters + feature source → Designspace → fontmake/ufo2ft/fontTools varLib → static OTF/TTF and selected Variable TTF → fontTools WOFF2 → table/shape/render QA`.

**Observed spike:** [`spikes/variable-build`](../spikes/variable-build/README.md) generated two original UFO masters and a Designspace weight axis; `fontmake==3.11.0` built static OTF/TTF and a variable TTF with `fvar/gvar/HVAR/MVAR`. WOFF2 requires `brotli` in the isolated Python environment; after installing it, compression is checked separately. A two-glyph spike proves toolchain connectivity, not production typography. [fontmake docs](https://github.com/googlefonts/fontmake/blob/main/README.md), [fontTools varLib](https://fonttools.readthedocs.io/en/latest/varLib/index.html), [Designspace specification](https://fonttools.readthedocs.io/en/latest/designspaceLib/index.html).

Validation gates before export: schema and range checks; deterministic source hash; glyph coverage; Unicode uniqueness; closed contours/direction/self-intersection scan; master contour/component compatibility; advance/sidebearing sanity; mark anchors; GSUB/GPOS compilation; `fontbakery`-style checks when product matures; HarfBuzz shaping and image proofs for Latin/Cyrillic. Track source hash, compiler versions, build profile and diagnostics in manifest. Reject incompatible variable builds with a specific glyph/master error; allow static export of separately valid switch branches. Build in an isolated worker with time/memory/output caps. Generated UFO/Designspace are artifacts, not the canonical editable project.
